# Corporate Cloud Security Lab: Infrastructure & Cloud Security Engineering

Практический проект по проектированию, развёртыванию и защите корпоративной облачной инфраструктуры на базе T1 Cloud (OpenStack) и Ubuntu Server 24.04 LTS.

## Цель и контекст
Цель проекта — отработка практических навыков Infrastructure Security и Cloud Security Engineer на базе реальной (хотя и учебной) инфраструктуры. В отличие от изолированных лабораторных работ, здесь строится **единая экосистема**: от сетевой сегментации до сбора логов и реагирования на инциденты (Incident Response).

## Архитектура и Текущее состояние
Вся инфраструктура развернута в облаке T1 Cloud (виртуализация KVM/OpenStack Nova).
На данный момент развернуты две виртуальные машины в единой подсети `10.20.0.0/24` (lab-subnet):
*   **kate-labb (10.20.0.4)** — Primary Server. Используется как основная защищаемая нода (Web/App сервер в будущем).
*   **kate-labb2 (10.20.0.5)** — Secondary Server. Используется для тестирования сетевого взаимодействия и роли «сканера» (Security Testing).

**Сетевая модель (Defense in Depth):**
*   **Облачный уровень:** Security Groups в T1 Cloud фильтруют трафик на периметре.
*   **Хостовый уровень:** UFW (Uncomplicated Firewall) настроен по принципу `Default Deny Incoming` (запрещено всё, кроме явно разрешенного).

## Реализованные меры защиты (Highlights)

### 1. SSH Hardening (Защита точки входа)
*   Отключена парольная аутентификация (`PasswordAuthentication no`). Вход строго по SSH-ключам.
*   Запрещен прямой вход под пользователем `root` (`PermitRootLogin no`).
*   Конфигурация вынесена в изолированный файл `/etc/ssh/sshd_config.d/00-lab-hardening.conf` с префиксом `00-` для приоритетного применения.

### 2. Host-based Firewall (UFW)
*   Входящий трафик по умолчанию запрещен (`default deny incoming`).
*   Исходящий трафик разрешен (`allow outgoing`).
*   Открыт только порт `22/tcp` (SSH).

### 3. Защита от брутфорса (Fail2ban)
*   Настроен `jail` (правило) для сервиса SSH.
*   Логика: 5 неудачных попыток ввода за 10 минут приводят к блокировке IP-адреса нарушителя на 15 минут через правила файрвола.
*   Интеграция с `systemd-journald` для чтения логов (вместо устаревших текстовых файлов).

### 4. Аудит системы (auditd)
*   Настроены правила ядра (syscall rules) для отслеживания изменений критических файлов (`/etc/passwd`, `/etc/sudoers`).
*   Настроено правило `root_cmd`: фиксация всех команд, выполненных с привилегиями root (euid=0) реальными пользователями (auid>=1000). Это позволяет отслеживать эскалацию привилегий.

### 5. Управление доступом (Access Control)
*   Создана модель ролевого доступа (RBAC) на уровне ОС.
*   Настроены группы (`appadmins`) и права на директории (`/opt/corporate-app` — права `750`, владелец `root:appadmins`).
*   Проведен аудит SUID/SGID бинарников (сверка с эталоном Ubuntu) и прав на файлы теневых паролей (`/etc/shadow`).
